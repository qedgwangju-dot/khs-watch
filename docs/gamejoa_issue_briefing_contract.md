# 실시간 핵심 뉴스 레이더: 하루 두 번 이슈 브리핑

- 목적: 기존 실시간 속보는 그대로 유지하면서, 증시에 영향을 주는 확인된 이슈를 장전과 장 마감에 정리한다.
- 시각: 06:30 KST 장전과 16:30 KST 장 마감. 06:45와 16:45는 동일 슬롯의 누락 복구용 백업이며 이미 예약됐으면 발송하지 않는다. GitHub Actions 지연과 수집 시간 때문에 실제 수신은 더 늦을 수 있다.
- 기사 시간: 장전은 전일 15:30 이상 당일 06:30 미만, 장 마감은 당일 06:30 이상 15:30 미만. 출력에 실제 조회 시각과 구간을 표시한다. 경계는 중복되지 않는다.
- 기사량과 전반·후반 건수는 해당 실행에서 수집한 URL 중복 제거 표본이다. 전체 기사량, SNS 반응, 검색량, 전수 결과 또는 미래의 확산 보장으로 표시하지 않는다.
- 제목과 핵심은 원문 본문을 확인한 기사로만 구성한다. 기존 레이더의 본문·시장 관련성 검증을 적용하며, 본문 미확인 또는 수집 실패가 있으면 부분 확인으로 표시한다. 동일 사건 재인용을 한 이슈로 묶는다. 이미 속보로 발송한 사건은 기본적으로 제외하되 표본 내 기사 2건 이상으로 확산을 집계할 수 있을 때만 `기존 속보 이슈 재정리`로 한 번 표시한다. 서로 다른 공식 단계나 신규 수치는 별도 사실로 유지한다.
- 종목은 거래소 KIND 상장회사 목록과 기사 제목·확인된 핵심의 직접 언급이 일치할 때만 표시한다. 관련주·수혜주 확정이나 매수 추천이 아니다. 종목 목록을 확인하지 못하면 종목 연결을 생략한다.
- 가격은 네이버 금융 일봉의 심볼과 회사명을 대조하고, 정규장 종료 전 당일 봉을 제외한다. 제공처의 종가와 직전 완료 일봉으로 등락률을 계산하며 기준 거래일을 표시한다. 시간외는 반영하지 않는다. 확인 실패 시 `종가 확인 불가`로 표시한다.
- 외화는 기존 환산 도구를 사용한다. 환율이 없으면 추정하지 않고 확인 불가로 표시하며, 원본 통화와 출처 기준을 증거 JSON에 보관한다.
- 발송 전에 GitHub main의 실시간 레이더 발송 이력을 다시 읽는다. 별도의 슬롯별 발송 예약은 GitHub Contents API의 파일 SHA 비교로 선점한다. 같은 슬롯의 재실행은 예약만 남았더라도 재발송하지 않는다. 텔레그램 요청 결과가 불명확한 경우에도 자동 재시도하지 않으며, 해당 Actions 결과를 확인해야 한다. 다른 워크플로가 동시에 보내는 경우까지 완전한 원자적 중복 차단을 보장하지는 않는다.
- workflow_dispatch의 기본은 무발송 검증이다. 실제 송출은 main에서 해당 시각의 2시간 이내에만 가능하다. PR 실행은 무발송이다.
- 검증: `python scripts/test_gamejoa_issue_briefing.py`; `GAMEJOA_INTEGRATION_TEST=true`는 거래소 목록과 네이버 일봉을 실제 조회한다. Actions artifact의 `gamejoa_issue_briefing.json`에서 출처 제한과 `delivery_status`, `message_id`를 확인한다. 실행 성공과 실제 텔레그램 발송은 별개다.
