# 전쟁 감시 알림 미발송 및 RSS 수집 복구 검증

## 실제 미발송 원인

- 5분 예약 워크플로는 active였으나 2026-10-13 20:24:25 KST 실행 `38389990094` 이후 자연 예약 실행이 생성되지 않았다. 조회 기준은 2026-10-14 00:12 KST다. 예약 생성 공백의 근본 원인은 미확정이다.
- 20:24 실행은 실제 수집 227개 중 221개 성공, 6개 실패로 발송·pending·seen 갱신 없이 중단됐다. 당시 실패는 Bing RSS 형식 오류였다. 아티팩트 `11808531754`의 ZIP SHA256은 `0d378a2b9b40a1e9f4f9627e43df41d554e5fbbf50104065310a6b1c18cb22c3`이다.
- 최신 #297 main 실행 `38397318131`은 DRY_RUN=true였고 실제 전송하지 않았다. 이후 자연 실행이 없으므로 새 기사 없음으로 미발송 이유를 설명할 수 없다.
- 사용자의 미발송 문제 제기에 따라 최신 main을 정상 모드로 한 번 dispatch했다. `38420536006`의 TELEGRAM_TEST=false, DRY_RUN=false, 실제 checkout `ff49a09e05f7b01a90ebaa95ed3f5da95b2aafb5`를 확인했다. 2026-10-14 00:15:46 KST 요청 후 실제 수집 226/227 성공, 중동 긴급 검색 한 항목 실패로 00:17에 중단됐다. Telegram·pending·seen은 갱신되지 않았다.
- 이 정상 실행의 아티팩트 `11825244117` ZIP SHA256은 `74f61d3a117731502e4816c20cbf77786365fb1ad5b8a3b5f10d74e5895385dd`이다. 실운영 판단은 coverage.json 및 조건 검사 단계로 했다. 오프라인 회귀의 의도된 실패 로그를 운영 오류로 집계하지 않았다.

## 확인된 수집 오류

실패 항목 `__BING_MIDDLE_EAST_EMERGENCY__`의 다섯 하위 검색 중 한 요청이 RSS/Atom 형식이 아닌 361바이트 응답을 반환했다. 두 실행에서 오류 해시 접두사 `67168c0a5fb6`가 같았다. 당시 코드가 오류 원문을 저장하지 않아 해당 361바이트의 정확한 내용은 미검증이다.

동일 공개 URL을 2026-10-14 00:20:54 KST 정상 HTTP 요청으로 조회했을 때는 HTTP 200, application/xml, 정상 RSS 1297바이트를 반환했다. SHA256은 `0c889fc4fbbbd9f37bc3af3d781c86617287c1519a00fdb8a24f922411a6e27d`이다. 이는 별도 환경의 이후 응답이며 GitHub runner의 과거 실패 응답이 정상이라는 증거는 아니다.

정상 실행에 기록된 Truth Social/AP HTTP403, GDELT HTTP429는 기존 대체 조회에서 회복된 항목이었다. 최종 실패는 위 Bing RSS 한 항목이다. 접근 거부를 해제하거나 우회하지 않는다.

## 보강

1. 잘못된 RSS 응답의 원문을 오류 객체에 연결하고 coverage에 바이트 수·SHA256·base64를 보존한다. 64KiB를 넘으면 잘림을 명시한다.
2. 첫 전체 수집을 마친 뒤 RSS 형식 오류만 있던 감시 항목을 한 번 더 조회한다. 기존 요청 URL·검색어·사용자 에이전트·227개 감시 범위·파서·최종 의미 검사를 유지한다.
3. 기존 전체 수집 deadline을 연장하지 않는다. HTTP401/403/429, 접근 차단, 다른 유형의 실패가 섞인 항목, 열린 제공처 circuit은 재조회하지 않는다.
4. 최초 실패 기록을 initial_attempt에 남기고 재조회 성공의 응답만 원래 순서로 재생한다. 재조회 후에도 한 항목이라도 불완전하거나 최종 검증이 실패하면 발송·상태 갱신을 차단한다.

기존 기사 분류·중복 규칙, 예약 */5, 발송 대상·권한·설정·seen 이력은 변경하지 않는다. 다른 곳에서 수정 중인 #278의 세 파일, KOSPI #283, 크립토·국채·KOFIA 작업을 수정하지 않는다. 테스트용 시장 알림·연결 테스트를 발송하지 않는다.

## 검증 구분

- 로컬 Python 컴파일 및 응답 원문/해시·재조회 허용/차단 검사 통과.
- Linux의 기존 19개 runtime 검사에 6개 회귀 사례를 추가했다: 실제 중동 검색 경로의 동일 다섯 요청 재조회·재생, 일시적 RSS 회복, 지속 오류 차단, 총시간 제한·작업자 정리, 혼합 접근 거부 차단, 실제 오류 원문 보존.
- 원격 CI, 새 코드의 실제 수집·재조회, 실제 Telegram 발송 및 저장은 각각 해당 Actions/아티팩트 증거로 판정한다.
- 수집 복구와 자연 예약 연속성은 별개다. 수동 실행 성공을 5분 예약 정상화로 판정하지 않는다. 원문 공표시각·기사 본문·독립 시장가격의 기존 미검증 표시는 유지한다.
