# 데이터센터 알림 구조 판단 원칙

기존 GitHub Actions → Python → Telegram 운영 경로를 유지한다.

알림 추가 요청이 들어오면 먼저 기존 알림 업그레이드와 별도 알림 중 어느 쪽이 더 읽기 쉽고 정확한지 판단한다.

- 같은 질문·같은 실행단계·같은 상태값을 보완하는 정보면 기존 알림을 업그레이드한다.
- 서로 다른 핵심 질문, 독립된 시간표, 별도 상태값과 실패모드를 가진 정보면 같은 워크플로 안에서 별도 Python/상태 파일/Telegram 메시지로 분리한다.
- 새 봇이나 새 워크플로는 꼭 필요한 경우가 아니면 만들지 않는다.
- 분리하더라도 서로 연결되는 핵심 지표는 각 알림 상단에서 한 줄로 교차 참조한다.
- 가독성을 위해 내용 자체를 줄이지 않고, 핵심 변화 → 현재 숫자 → 실행단계 → 투자 의미 → 원문 순으로 배치한다.
- 영문 제목은 한국어로 번역하고 식별 필수 고유명사만 원문을 유지한다.
- 외화 금액은 항상 같은 줄에 최신 환율 기준 원화 환산을 붙인다.
- Telegram 본문은 기본체를 사용하고 기울임체를 사용하지 않는다.
- 코드 반영, GitHub Actions 성공, Telegram 실제 송출 성공을 각각 구분해 확인한다.
