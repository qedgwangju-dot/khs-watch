# 코스피·코스닥 순매수 급증 알림 공통 기준

두 시장의 수급 알림은 `Watch._build_market_flow_surge_alert`,
`Watch._surge_industry_context`, `confirm_flow_surge`를 함께 사용한다.
코스닥은 외국인·기관·개인·투신·금융투자를 각각 감지한다.
한쪽만 바꾸는 변경은 두 시장·세 투자자를 함께 대조하는 회귀 검사를 통과해야 한다.

- 표시 순서는 시장·투자자·구간 → 실제 현물 누적값 변화 → 업종 증가 순위 또는 보류 사유 →
  확인 범위·단위 제한 → 교차검증 → 감지 기준 → 해석 한계·출처다.
- 업종은 같은 시장·투자자·거래일과 실제 현물 5분 구간으로 계산한다.
  종료 누적값에서 시작 누적값을 빼며 각 기준점 시차는 30초 이내다.
- 확인한 업종이 일부이면 부분 순위와 확인 수/대상 수를 표시한다.
  금액 단위가 확인되지 않으면 업종 금액은 환산하지 않는다.
- 프로그램 전체·차익·비차익의 수치 검산과 원천 공표시각 검증을 구분한다.
  조회시각만 있거나 시작·종료 중 하나의 공표시각이 확인되지 않으면 프로그램
  수치는 보조 정보로 표시하되, 이를 근거로 수급 신호의 확신도를 높이지 않는다.
- 현물 증가나 표본이 없으면 업종 순위를 보류한다. 선물 급증으로 업종을 추정하지 않는다.
  업종 자료 장애가 있으면 시장 알림은 보존하고 업종 부분에 실패 사유를 표시한다.
- 두 차례 확인은 원자료 시각이 10초 이상 진전하고 해당 감지 채널의 누적 순매수가 증가해야 한다.
  동일 값의 시각 갱신, 누적값 감소, 감지 채널 변경은 두 번째 확인이 아니다.
  장전 표본 제외·20분 중복 방지·시장별 상태 분리를 유지한다.
- 감지 금액은 시장별 설정을 유지하며 본문에 명시한다.
  코스닥은 현물 100억원 이상 150억원 미만에서 예비 경보, 150억원 이상에서 본 급증 알림이다.
  150억원 이상이면 본 알림만 보내며, 예비 경보와 본 알림은 상태·20분 중복 제한을 분리해
  예비 경보가 본 알림을 가리지 않게 한다. 최근 본 알림이 발송되거나 발송 여부가 불확실한
  경우에는 같은 주체의 예비 경보를 20분간 억제한다. 코스피는 현물 900억원 또는 선물 1,300억원,
  또는 현물 300억원·선물 450억원 동시 증가다.
  KOSPI200 선물을 코스닥의 확인값으로 쓰지 않는다.
- 투신·금융투자는 기관의 하위 항목이다. 각각의 신호로 표시하되 기관과 합산하거나
  독립 집단의 동조로 세지 않는다. 금융투자 현물 원값이 없거나 불일치하면 감지를 보류하고,
  확인된 금융투자 업종 원자료가 없을 때 업종 순위도 보류한다.
- 원자료와 업종 상세·실제 본문 SHA256·시장·투자자·계약 버전을 기존 전송 증거에 보존한다.
  코드 반영, 실제 실행의 코드 로딩, Telegram 발송·저장은 각기 별도 증거로 확인한다.

이 계약은 두 시장의 순매수 급증 알림에 적용한다. 급락 사건의 시작·확대·종료,
장마감 프로그램 수급 등 다른 종류의 알림은 해당 사건의 원래 기준을 유지한다.

## 전송·수신 대상 검증

- 두 시장의 급락·확대·종료·장마감·정밀분해·순매수 급증은 같은 전송기를 사용한다.
- `getMe`의 봇뿐 아니라 `getChat`의 실제 대상과 설정을 대조한다. 보조 대상 선택도 명시한다.
  수신 대상 ID와 토큰은 공개하지 않고 대상 해시·채팅 유형만 보존한다.
- 요청 HTML과 해시, Telegram이 반환한 표시 본문·본문 해시·대상 해시·서버 시각·메시지 ID,
  실제 코드와 실행 ID, 시장·알림 종류·사건 시각을 `out/market_alert_delivery/`에 보존한다.
  HTTP 응답 전체 대신 개인정보를 제거한 필드와 원응답 해시를 보존한다.
- 전송 성공 전에 사건을 발송 완료로 만들거나 마지막 발송 낙폭을 진전시키지 않는다.
  확인된 승인 기록은 상태 저장 실패 뒤에도 재사용해 같은 메시지를 다시 보내지 않는다.
- 전송 POST 뒤 응답이 유실되면 승인 여부 미확인 상태를 남기고 해당 경로의 자동 재전송을
  차단한다. `in_flight`/`uncertain`을 확인 없이 삭제하거나 이전 실행을 다시 보내지 않는다.
- 메시지 ID와 서버 승인, 사용자 기기의 실제 수신은 별도 증거다.
  상태 로그는 매분 두 시장의 마지막 시세 수신 나이를 표시하며 실행 중 배지만으로 정상 판정하지 않는다.
